# Codex Sleep Watcher 设计

日期：2026-07-11

## 目标

构建一个原生 macOS 菜单栏 App，让用户为“下一项 Codex 桌面 App 任务”启用监控。任务执行期间阻止系统因空闲进入睡眠；任务停止执行后，无论结果是成功、失败、取消、Codex 退出，还是进入等待用户确认状态，都在可取消的倒计时结束后让 Mac 休眠。

## 非目标

- 不读取或修改 Codex 的内部数据库、日志格式或私有文件。
- 不自动监控所有 Codex 任务；每次由用户明确启用“监控下一项任务”。
- 不绕过合盖、低电量、系统管理策略或用户主动触发的休眠。
- 不在第一版提供 App Store 发布、云同步或远程控制。

## 方案选择

采用原生 Swift/SwiftUI 菜单栏 App，通过 macOS Accessibility API 观察 Codex 的可访问性状态。

放弃纯标记文件方案，因为任务被取消、Codex 崩溃或等待用户确认时，任务本身无法可靠写入标记。放弃读取 Codex 内部状态文件，因为该接口未公开，升级后容易失效。

## 用户体验

App 以菜单栏图标运行，不显示 Dock 图标。菜单提供：

- “监控下一项 Codex 任务”
- 当前状态：未启用、等待任务开始、任务执行中、休眠倒计时
- 取消监控
- 立即休眠
- 休眠延迟：0、15、30、60 秒，默认 30 秒
- “保持屏幕常亮”开关，默认关闭
- “登录时启动”开关，默认关闭

首次启用监控时，App 检查辅助功能权限。未授权时展示用途说明并打开系统设置中的辅助功能页面。未取得权限前不进入监控状态，也不建立防休眠断言。

用户点击“监控下一项 Codex 任务”后，App 进入等待状态。只有实际检测到 Codex 从空闲转为执行中后，才把本次任务认定为已开始。若始终没有检测到任务开始，App 不会自行休眠。

任务停止后进入倒计时，菜单栏图标和系统通知显示剩余时间。用户可以在倒计时内取消休眠。倒计时结束后 App 请求系统立即休眠。

## 状态机

状态流为：

`idle -> armed -> active -> countdown -> sleeping -> idle`

- `idle`：不监控，不持有电源断言。
- `armed`：等待下一项 Codex 任务开始，不持有电源断言。
- `active`：已确认任务开始，持有防空闲睡眠断言。
- `countdown`：任务已停止，继续持有断言，避免倒计时期间系统先行休眠。
- `sleeping`：释放断言并请求系统休眠。

在 `armed`、`active` 或 `countdown` 中执行“取消监控”，均回到 `idle` 并释放已有断言。App 退出或崩溃时，macOS 自动清理进程持有的电源断言。

## Codex 活动检测

`CodexActivityDetector` 只访问 Codex 进程的可访问性元素，不读取任务正文。检测器使用独立适配层，避免 Codex UI 变化影响其他组件。

执行中状态由以下任一信号确认：

- 存在可访问的“停止/取消当前执行”控件；
- 存在表示生成或工具执行的忙碌/进度元素。

只有在 `armed` 状态下连续两次采样检测到执行中信号，才进入 `active`，以过滤短暂 UI 变化。

进入 `active` 后，以下任一情况视为任务停止：

- 执行中信号连续两次消失；
- 出现等待授权、确认或用户输入的交互界面；
- Codex 进程退出、崩溃或其主窗口关闭。

默认每秒采样一次。两次连续采样的防抖意味着正常情况下最多约两秒识别状态切换。适配器集中保存可访问性角色、标识符与标题匹配规则，并提供诊断模式，只输出角色和标识符，不记录任务内容。

若辅助功能查询返回权限丢失或不可恢复错误，App 采用安全失败策略：停止监控、释放电源断言、显示错误通知，并且不触发休眠。

## 电源管理与休眠

`PowerAssertionController` 使用 IOKit 创建防空闲睡眠断言。默认允许显示器熄灭；启用“保持屏幕常亮”后额外创建显示器防休眠断言。所有断言都有唯一所有者，并在状态退出、取消监控和 App 终止时释放。

`SystemSleeper` 将系统休眠封装为可替换接口。生产实现优先调用 macOS 电源管理接口；若当前系统拒绝该调用，则显示明确错误，不反复尝试，也不修改永久电源设置。

## 组件边界

- `AppStateController`：状态机和用户操作入口。
- `CodexActivityDetector`：将 Codex 可访问性树转换为 `idle/running/waiting/unavailable` 信号。
- `PowerAssertionController`：创建和释放系统、显示器电源断言。
- `SleepCountdownController`：管理倒计时和取消操作。
- `SystemSleeper`：请求系统休眠。
- `NotificationController`：权限、倒计时通知和错误通知。
- `SettingsStore`：保存延迟、屏幕常亮和登录启动偏好。
- `MenuBarView`：展示状态和操作，不包含检测或电源逻辑。

组件通过协议注入，状态机不直接依赖 Accessibility、IOKit 或真实休眠调用，从而可以安全测试。

## 权限与隐私

- 辅助功能权限：必需，仅用于识别 Codex 是否正在执行或等待交互。
- 通知权限：建议，用于倒计时和错误提示；拒绝后菜单栏倒计时仍可使用。
- 登录项权限：仅在用户启用“登录时启动”时请求。
- App 不需要网络权限，不上传遥测，不保存 Codex 任务内容。

## 错误处理

- Codex 未安装或未运行：保持 `armed`，菜单显示等待状态。
- 辅助功能权限缺失或被撤销：停止监控，不休眠。
- 无法建立防休眠断言：停止本次监控并通知用户，避免产生“以为电脑会保持唤醒”的错误预期。
- 休眠请求失败：显示错误并回到 `idle`，不循环重试。
- App 被退出：断言随进程清理，不留下永久系统配置。

## 测试策略

自动化测试绝不调用真实系统休眠。

- 状态机单元测试：覆盖正常完成、失败、取消、等待确认、Codex 退出、用户取消监控和从未检测到任务开始。
- 防抖测试：单次瞬态信号不会开始或结束任务。
- 电源断言测试：只在 `active/countdown` 持有，所有退出路径均释放。
- 倒计时测试：时间到调用一次假的 `SystemSleeper`；取消后不调用。
- 权限和检测错误测试：错误时释放断言且不休眠。
- 设置持久化测试：延迟、屏幕常亮和登录启动值正确恢复。
- 手动验收：在真实 Codex 桌面 App 上分别验证成功、失败、取消、等待确认和 App 退出五条路径。

## 验收标准

1. 用户可从菜单栏为下一项 Codex 任务启用一次性监控。
2. 只有检测到任务实际开始后，工具才可能触发后续休眠。
3. 任务执行期间 Mac 不因空闲睡眠；屏幕默认允许熄灭。
4. 成功、失败、取消、等待确认或 Codex 退出均启动可取消倒计时。
5. 用户取消监控或倒计时后不会休眠。
6. 权限、检测或电源断言错误时采用安全失败，不触发休眠。
7. 自动化测试不会让开发机器真实休眠。
8. 项目可生成一个可双击运行的本地 `.app`，并附带安装与授权说明。
