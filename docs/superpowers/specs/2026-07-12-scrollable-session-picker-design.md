# 可滚动会话选择器与状态语义设计

## 背景

App Server 已确认能返回多个项目的最近会话，但当前 `MenuBarExtra` 使用系统菜单样式，并动态插入最多 20 个包含双行 `VStack` 的按钮。macOS 日志曾报告 SwiftUI 菜单项视图错配，实际界面只显示部分会话。当前“已停止”文案还把一次 Codex 回合结束误写成整个会话停止。

## 已确认方案

采用菜单栏弹窗式界面。点击月亮图标后显示固定宽高的 SwiftUI 弹窗，其中会话区域独立滚动，设置与操作区域保持可见。

## 会话列表

- 展示最近 20 个 App Server 会话，以及仅由 Hooks 发现且仍处于实时状态的会话。
- 每行显示会话名称、项目目录末级名称、短会话 ID 和状态。
- 选中行有明确高亮与“正在观测”标识。
- 点击未选中的会话开始观测；点击其他会话会先释放旧防休眠断言，再切换目标。
- 刷新不会移除选中目标，也不会覆盖更新的 Hook 状态。

## 状态语义

- `SessionStart`：运行中。
- `UserPromptSubmit`：运行中。
- `PermissionRequest`：等待授权。
- `Stop`：本轮已完成。该状态仍允许用户继续观测下一轮任务。
- App Server 能发现但尚未收到 Hook：尚未收到事件。

休眠触发逻辑保持现有行为：只有选中目标的 `Stop` 或 `PermissionRequest` 触发倒计时。状态文案调整不改变这一规则。

## 布局

- 弹窗宽约 460 点，高约 600 点。
- 顶部显示当前运行状态和刷新按钮。
- 中部为最大高度约 320 点的 `ScrollView`，承载会话卡片。
- 底部包含 Hooks、休眠延迟、其他会话策略、立即休眠与退出操作。
- 空列表时显示明确引导，不折叠其他操作。

## 验收与端到端测试

- App Server 返回的不同项目会话均能在滚动列表中找到。
- 同时创建两个不同工作目录的临时 Codex 会话后，两者都显示为运行中。
- 一个临时会话完成或被停止后，仅该会话变为“本轮已完成”。
- 另一个仍运行的会话保持“运行中”。
- 选中目标在刷新后仍保持高亮。
- 两个临时测试会话及其子进程在测试结束后全部终止。
- 自动化测试、Debug 构建和 Release 构建通过；用户确认前不制作最终发布包。
