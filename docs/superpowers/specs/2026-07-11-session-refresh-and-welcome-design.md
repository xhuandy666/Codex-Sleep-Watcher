# 会话刷新与首次启动提示设计

## 背景

Codex Sleep Watcher 当前通过独立启动的 Codex App Server 查询会话。该进程返回的任务运行状态属于自身运行时，Codex Desktop 中已经打开的任务通常显示为 `notLoaded`。现有实现只保留 `active` 任务，导致用户点击“刷新会话”后列表清空。

同时，应用是仅菜单栏运行的 `LSUIElement` App，首次双击不会出现窗口或 Dock 图标，用户容易误以为没有启动。

## 目标

- 刷新时显示最近的 Codex 会话，不因 `notLoaded` 状态而消失。
- 使用 Hooks 事件作为任务是否运行、等待授权或停止的实时依据。
- 刷新后保留当前观测目标。
- 首次启动自动显示醒目的欢迎窗口。
- 菜单栏提供“使用说明…”入口，允许再次打开欢迎窗口。
- 测试版使用真实系统休眠行为。

## 会话数据设计

App Server 的 `thread/list` 仅承担会话发现和元数据读取，最多展示最近更新的 20 个未归档会话。`active`、`idle` 和 `notLoaded` 均可成为候选项，不再因为 App Server 返回 `notLoaded` 而过滤。

会话的实时状态由 `SessionRegistry` 合并 Hooks 事件决定：

- `UserPromptSubmit`：运行中。
- `PermissionRequest`：等待授权。
- `Stop`：已停止。
- 尚未收到 Hook 事件：状态未知。

App Server 返回的 `active` 仅作为初始提示，不能覆盖时间更新的 Hook 状态。刷新只更新名称、目录和更新时间，并保留已选择的会话 ID；若目标不在最新 20 条结果中，仍把目标保留在列表中，直到用户取消观测。

用户可以从最近会话中选择目标。选择后 App 立即建立防休眠断言；目标后续发出 `Stop` 或 `PermissionRequest` 时，沿用现有倒计时和休眠策略。

## 首次启动体验

首次启动时显示普通 macOS 欢迎窗口，明确说明：

1. App 启动后位于菜单栏月亮图标中。
2. 首次使用需要安装并在 Codex 中信任 Hooks。
3. 刷新会话并选择观测目标。
4. 目标结束后 App 将按设置让 Mac 真实休眠。

窗口提供“开始使用”按钮，关闭窗口并记录已展示标记。后续启动不自动弹出。菜单栏增加“使用说明…”，可随时重新打开；手动打开不会改变业务状态。

## 错误与状态反馈

- 刷新失败时保留现有会话列表，只更新状态文字，不清空 UI。
- 无候选会话时显示明确提示，建议先在 Codex 创建或运行任务。
- 欢迎窗口不阻塞菜单栏初始化和 Hook 事件监听。

## 测试与验收

- `notLoaded`、`idle` 和 `active` 会话均进入最近会话候选列表。
- 最近会话最多显示 20 个并按更新时间倒序排列。
- Hook 状态不会被刷新返回的旧 App Server 状态覆盖。
- 刷新后观测目标仍存在且保持选中。
- 刷新失败时原列表仍保留。
- 首次启动自动显示欢迎窗口；关闭后再次启动不自动显示。
- 菜单栏“使用说明…”可重新打开欢迎窗口。
- 自动化测试、Debug 构建通过，并以真实休眠路径进行手工测试交付；正式打包在用户确认后进行。

## 不在本次范围

- 登录时自动启动。
- 系统通知或休眠前通知中心操作。
- 直接读取或修改 Codex Desktop 私有数据库。
